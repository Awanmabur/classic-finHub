# ClassicFin Hub app audit

26 November 2026, Kampala time

## Findings and fixes

| Area | Finding | Fix |
| --- | --- | --- |
| Profile and navigation | The account footer left 18px between the profile card and its actions. Two tenant menu links obscured the destination. | The gap is 6px on phone, tablet and desktop. Payout by PIN opens its current form directly. Loan Applications jumps to the applications on the loan page. |
| Cash Day and money accounts | Older verified transactions could block closing. Funding and top-ups could change expected cash while a drawer was being recounted. | Cash Day recognizes verified legacy records. New cash postings wait for reconciliation. Historical corrections and the owner’s reconciliation and closing actions remain available. |
| Loans and Airtime | Views could revert to all branches after permission checks, despite a selected reporting branch. | Lists, summaries, records and receipts respect the reporting branch. Entry forms select products from the authorized operating branch. |
| Platform administration | Tenant and subscription lists stopped after 100 records. The audit trail had a similar limit. Legacy subscription dates and statuses could display incorrectly. | Tenant and subscription search spans stored workspaces. All three lists can page to older records. Plan status uses the access rules from the backend. Timezone edits and their audit records now commit together. |
| Appointments | A malformed appointment date could break the page and allow the appointment to be marked complete. | The page renders those dates safely. Completion requires a valid start time that has passed. |
| Sign-in and recovery | Accepted form URL variants could miss CSRF token setup. A normalized redirect could escape the intended workspace. Password reset links could survive changes to the account. | Accepted forms receive CSRF protection on their supported paths. Redirect destinations are checked after normalization. Reset links match the credential version at issue, successful resets revoke existing sessions, and missing accounts and email delivery failures return the same public status and message. |
| Search and AI discovery | Directory, profile and sitemap eligibility could disagree. URL aliases dropped query parameters. The production SEO verifier expected an outdated sitemap and crawler policy. | Public listings, profile routes and sitemap entries share the eligibility rules. Canonical URLs preserve query parameters during redirects. Filtered directory results, draft profiles and sensitive routes carry appropriate crawler restrictions. The verification script and public `llms.txt` reading guide reflect current policy. The public guides describe owner-led account funding, Cash Day and General reports. |
| Release and worker health | Concurrent standalone releases could change the live version after preflight. A fresh heartbeat from a different process could make a replacement worker appear ready. | Standalone release paths share a lock. The pinned release checks the live revision again before cutover. Container probes require a fresh heartbeat from the worker running inside that container. |

## Verification

- Chromium measured the profile gap at 6px at 320, 390, 768 and 1440px. The authenticated tenant browser review visited 31 owner links and three Reports Analyst links. It also checked the mobile control order, transaction dialogs and horizontal scrolling in Recent activity.
- Chromium exercised the platform tenant, subscription, audit and settings pages at 320, 390 and 1440px, including search and older records. The HTTP integration searched across more than 100 seeded tenants and checked legacy records and atomic timezone audit writes.
- Isolated financial integrations checked recount behavior and unchanged balances after rejected postings, legacy Cash Day closing, owner reconciliation, branch-scoped Loans and Airtime, customer accounts, funded transactions, expenses, banking, transfers and FX. A two-currency Mobile Money case checked atomic native-currency journals, retry behavior, rollback and rate availability.
- Authentication checks covered CSRF, normalized redirects, MFA, session revocation and masked recovery delivery failures. Recovery response timing and actual inbox delivery require separate evidence.
- Production-mode HTTP tests against disposable MongoDB verified canonical public URLs, directory pagination, sitemap, robots.txt, llms.txt, published profiles, legacy activation, hidden profiles and noindex responses.
- Worker tests covered readiness against disposable MongoDB for all three worker types and refusal when a different worker had a fresh heartbeat. The release fixtures covered live revision drift and rollback. The production and tenant backup Compose files passed configuration validation.

## Production checks still open

- The tested release needs to be applied on the production host. The live web and worker revisions, TLS readiness, production database permissions, and real email and SMS delivery still need live evidence.
- Production backup restoration and representative load remain outside this verification. Public crawl controls were tested at the application level. Search engine and AI indexing depend on the crawler.
- Cash Day reconciliation is direct for the owner. Existing independent controls for retail refunds remain in place.
